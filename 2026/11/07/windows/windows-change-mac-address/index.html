Windows 修改网卡 MAC 地址完全指南：从 NDIS 原理到一键脚本

排查网络问题时，ipconfig /all 里出现了一个陌生的物理地址，比如 52-5A-65-xx-xx-xx。它不像任何厂商的前缀，也想不起来是哪张网卡。再深挖一步，会发现某张网卡当前用的 MAC 根本不是出厂值，而是被人（或者某个软件）改过的。

这类问题背后有几个容易混淆的事实：MAC 地址不是”写死”的，Windows 允许驱动用一个注册表值覆盖出厂地址；有线网卡和无线网卡对新地址的限制不一样；PowerShell 的几个 cmdlet 在参数设计上并不对称。另外，常有人问”TeamViewer 是怎么改 MAC 的”，答案是它根本不改，只读。

本文从 MAC 地址的位结构讲起，梳理 Windows 网络栈中 MAC 覆盖的实际机制，然后给出一个可直接使用的 PowerShell 脚本，最后整理排错过程中踩过的坑。读完之后，你应该能：

  • 根据一个 MAC 地址反查到它属于本机哪张网卡，并判断它是不是被改过的；
  • 理解”网络地址 / Locally Administered Address”这个设置在驱动层到底做了什么；
  • 用三种方式（图形界面、PowerShell、注册表）安全地修改和恢复 MAC；
  • 避开地址格式、调用方式、脚本编码等常见陷阱。

一、MAC 地址的位结构

MAC 地址（EUI-48）是 48 位、6 个字节，通常写成 12 位十六进制。前 3 字节是 OUI（组织唯一标识符），由 IEEE 分配给厂商；后 3 字节由厂商自行分配。

真正决定”这个地址能不能用”的，是第一个字节的最低两位：

这两位落在第一个字节的低 4 位里，也就是十六进制写法中的第 2 个字符。所以只看第 2 位就能判断地址类型：

第 2 位 二进制 I/G（b0） U/L（b1） 含义
0、4、8、C xx00 0 单播 0 全球 厂商出厂的单播地址
2、6、A、E xx10 0 单播 1 本地 本地管理的单播地址（手动设置、随机 MAC）
1、5、9、D xx01 1 组播 0 全球 组播地址，网卡不能用作自身地址
3、7、B、F xx11 1 组播 1 本地 组播地址，同样不能用

二、Windows 是怎么”改”MAC 的

2.1 出厂地址从来没变过

网卡芯片的出厂地址存放在 EEPROM 或 NVM 里，Windows 修改 MAC 并不会动它。修改的实质是：让驱动在初始化时，用另一个地址代替出厂地址去收发帧。

因此一张网卡同时有两个地址：

名称 NDIS 对应的 OID（以太网） PowerShell 字段 说明
永久地址 OID_802_3_PERMANENT_ADDRESS PermanentAddress 芯片里烧录的出厂值
当前地址 OID_802_3_CURRENT_ADDRESS MacAddress 驱动实际使用的地址

无线网卡在 Native 802.11 模型下对应的是 OID_DOT11_* 系列，含义相同。

两者不相等，就说明有覆盖设置在生效。

  2. 读取时机：驱动在 MiniportInitializeEx 里调用 NdisReadNetworkAddress 读取这个值，所以修改后必须重启网卡（禁用再启用）才会生效。NDIS 只负责把字符串读出来，不做校验，地址是否合法由驱动自己判断。
  3. 是否支持由驱动决定：驱动的 INF 文件里如果声明了 Ndi\params\NetworkAddress，设备管理器的”高级”选项卡就会显示这一项。没有声明的驱动，即使手动写注册表，也可能完全不读。

2.3 同一个设置，三种叫法

不同驱动给这个参数起的显示名不一样，但底层关键字都是 NetworkAddress：

驱动 中文显示名 英文显示名
Intel 有线（e1d、e1r 等） 本地管理地址 Locally Administered Address
Realtek 有线 网络地址 Network Address
部分无线驱动 网络地址 Network Address

写脚本时应该按 RegistryKeyword 定位，而不是按显示名，否则换一台英文系统或者另一个品牌的网卡，脚本就失效了。

2.4 无线网卡的额外限制

从 Windows Vista/7 开始，大多数无线网卡驱动只接受本地管理的单播地址作为覆盖值，也就是第 2 位只能是 2、6、A、E。不满足的值通常会被忽略，网卡继续使用出厂地址，而且不会报错。这条规则来自社区长期积累的经验（例如 Technitium TMAC 的说明），微软没有在正式文档中明确记录，个别驱动的表现可能不同。

还有不少无线网卡驱动根本没有声明 NetworkAddress，笔者机器上的 Intel AX201 就是这样。这种网卡用任何修改方式都不会生效。

有线网卡没有这条限制，只要是单播地址（第 2 位为偶数）、不是全零即可。这个区别非常容易被忽略，后文排错部分会再提到。

2.5 系统自带的随机 MAC

Windows 10/11 的 Wi-Fi 有”随机硬件地址”功能（设置 → 网络和 Internet → WLAN）。开启后，系统会为每个网络生成一个本地管理地址，例如 F6-xx-xx-xx-xx-xx。这是另一套机制，由 WLAN 服务管理，不依赖驱动的 NetworkAddress 参数，只适用于无线网卡。网卡硬件不支持时，设置里不会出现这个开关。

三、关于 TeamViewer 与 MAC 地址

经常有人问”TeamViewer 是如何修改 MAC 地址的”。准确的说法是：TeamViewer 不修改 MAC，只读取 MAC。

TeamViewer ID 是根据本机硬件指纹生成的。官方没有公开算法，社区普遍认为在 Windows 上会用到主网卡 MAC、系统盘卷序列号以及安装时写入的注册表信息。一般认为 ID 第一次生成后会写入配置，以后启动时直接读取，不会每次重新计算。配置位置因版本而异：64 位系统上的 32 位版本在 HKLM\SOFTWARE\WOW6432Node\TeamViewer，64 位版本在 HKLM\SOFTWARE\TeamViewer。

TeamViewer 唯一会”产生” MAC 地址的地方是 VPN 组件。如果安装时勾选了这个可选组件，系统里会多出一块 TAP 虚拟网卡，地址由驱动生成，和物理网卡无关。

网上流传的”改 MAC 换 ID”工具是在操作系统层面修改 MAC，并清理 TeamViewer 的配置，跟 TeamViewer 本身无关。用这种方法绕过商业用途检测违反许可协议；如果确实是误判，应该走官方的商业用途重置申请。

五、实战二：三种修改方式

5.1 设备管理器（图形界面）

  1. 按 Win + X，选”设备管理器”，或者运行 devmgmt.msc。
  2. 展开”网络适配器”，右键目标网卡，选”属性”。
  3. 打开”高级”选项卡，在左侧列表中找到”网络地址”或”本地管理地址”。
  4. 选中”值”，输入 12 位十六进制，不要带分隔符，例如 021A2B3C4D5E。
  5. 点”确定”。网卡会自动重启，断网几秒属于正常现象。

恢复出厂地址：在同一位置选”不存在 / Not Present”。

5.3 注册表（高级选项里没有这一项时）

  1. 运行 regedit，先导出备份。
  2. 定位到 HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Class\{4d36e972-e325-11ce-bfc1-08002be10318}。
  3. 依次点开 0000、0001……，找到对应网卡的子键。最可靠的办法是比对 NetCfgInstanceId 和 Get-NetAdapter 返回的 InterfaceGuid，两者格式相同。也可以比对 DriverDesc，但要注意它对应的是设备名（InterfaceDescription），而不是”以太网”这类连接名；同型号网卡的 InterfaceDescription 会带 #2 之类的后缀，DriverDesc 没有。
  4. 新建字符串值，名称为 NetworkAddress，数据填写 021A2B3C4D5E。
  5. 禁用再启用网卡，或者重启电脑。

恢复：删除 NetworkAddress 值，再重启网卡。

驱动 INF 没有声明 NetworkAddress 时，这种方法能否生效完全取决于驱动是否调用了 NdisReadNetworkAddress。不少无线驱动不读这个值，写了也没有效果。

7.2 改完显示成功，但地址没变（无线网卡）

原因：给无线网卡设置了第 2 位不是 2/6/A/E 的地址，比如 0C-...，多数无线驱动会忽略这个值。另一种可能是驱动根本不支持覆盖，见 7.4。

排查：

PhysicalMediaType 为 Native 802.11 时，改用 02-...、06-... 这类地址。

7.3 有线网卡被错误拒绝

常见的错误写法是：把”第 2 位必须是 2/6/A/E”这条无线网卡的规则套用到所有网卡上，导致有线网卡想设置 0C-... 这类地址（例如克隆另一台设备的 MAC）时被拒绝。

修正方法是按网卡类型区分校验：有线网卡只要求单播（第 2 位为偶数），无线网卡才要求本地管理位。校验规则不应该比平台本身的限制更严格。

7.4 高级选项卡里没有”网络地址”

原因：驱动 INF 没有声明 NetworkAddress 参数。

排查：

这里不要加 -AllProperties，否则手工写进注册表的值也会出现在列表里。驱动不支持时，用 -RegistryKeyword NetworkAddress 单独查询会报”找不到任何匹配的 MSFT_NetAdapterAdvancedPropertySettingData 对象”。

九、最佳实践

  1. 改之前先记录出厂地址。PermanentAddress 一般能读到，但在虚拟化环境或某些驱动下可能为空。
  2. 优先使用本地管理地址（第 2 位为 2/6/A/E）。这类地址不会和任何厂商的出厂地址冲突，有线和无线网卡都能用。
  3. 按 RegistryKeyword 而不是 DisplayName 定位参数，脚本才能跨语言、跨驱动使用。
  4. 先校验、后提权。把能在普通权限下完成的检查放在前面，测试阶段就不会误改。
  5. 含中文的 .ps1 一律保存为 UTF-8 with BOM，以兼容 Windows PowerShell 5.1。
  6. 给出调用示例时同时写上 & "完整路径" 的形式，用户经常会把脚本放到别的目录、从 system32 运行。
  7. 校验规则与平台限制保持一致：无线网卡要求 2/6/A/E，有线网卡只要求单播。
  8. 修改后用 getmac /v 交叉验证，不要只相信 cmdlet 的返回值。
  9. 用 -Name 定位网卡时，确认只匹配到一张。Get-NetAdapter -Name 支持通配符，写错一个字符就可能把同一个地址写进多张网卡。
  10. 测试和修改分两个窗口：普通窗口里测试校验逻辑，确认无误后再到管理员窗口执行修改。
